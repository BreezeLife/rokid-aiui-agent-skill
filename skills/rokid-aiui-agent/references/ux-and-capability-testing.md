# Mandatory AIUI UX and capability testing

Read this for every AIUI project creation, implementation, code change, or review. The output is a project-specific UX matrix and a per-capability matrix, not a reference to a generic checklist. Keep capture manifests and artifacts in the repository-root `.aiui-evidence/` audit directory. That single reserved directory is excluded from the source fingerprint so evidence does not create a self-referential revision; no other ignored or hidden file is excluded.

Use [interaction-and-design.md](interaction-and-design.md) for the design rules, [runtime-capabilities.md](runtime-capabilities.md) for exact API support, and [debugging-and-release.md](debugging-and-release.md) for release flow. The selected-version official documentation and runnable samples remain authoritative.

## Authority and version boundary

The default stable source remains AIUI [`v0.17.0`](https://github.com/yodaos-project/AIUI/tree/88e70bb0382525c1a93ef077c2401dcc31a273ce). The current official `aiui-dev` [UX checklist](https://github.com/yodaos-project/AIUI/blob/63bb5f5efa2f0c11a2defca35bc00777150f43d2/skills/aiui-dev/references/checklist.md#L47-L57), [API/capability checks](https://github.com/yodaos-project/AIUI/blob/63bb5f5efa2f0c11a2defca35bc00777150f43d2/skills/aiui-dev/references/checklist.md#L59-L83), [executable validation](https://github.com/yodaos-project/AIUI/blob/63bb5f5efa2f0c11a2defca35bc00777150f43d2/skills/aiui-dev/references/checklist.md#L84-L100), and [evidence report rules](https://github.com/yodaos-project/AIUI/blob/63bb5f5efa2f0c11a2defca35bc00777150f43d2/skills/aiui-dev/references/checklist.md#L102-L110) support this mandatory test protocol.

That testing checklist belongs to commit `63bb5f5efa2f0c11a2defca35bc00777150f43d2`; it is a protocol source, not the canonical feature snapshot. The separately inspected AIUI 0.18 preview/additions source is commit [`8b19a87b4ba8b486c0dd4dd3fd32290d27891069`](https://github.com/yodaos-project/AIUI/tree/8b19a87b4ba8b486c0dd4dd3fd32290d27891069). Here, reuse its general testing discipline, not its feature availability, for a 0.17 target. The exact family policies and PASS bindings below are registered for 0.17 only. A 0.18 project may be inventoried, but every capability row remains `BLOCKED` until a separate 0.18 policy verifies that family's exact source, declaration, and PASS vocabulary. Never mechanically swap source commits and reuse a 0.17 policy. Keep Widgets, Agent Workers, and other newer features gated.

Before the matrices, emit only these seven metadata lines, in this order: `Project revision: <40-character commit|WORKTREE:SHA-256|UNAVAILABLE>`, `Canonical version: AIUI 0.17.0|AIUI 0.18.0`, `Import root: ...`, `Device/host: UNAVAILABLE|device=<Rokid model>; host=<host/build>; runtime=AIUI <version>`, `Supported surfaces: ...`, `Inputs: kind@gate,kind@gate,...|none`, and `Claimed capabilities: family@gate,family@gate,...`. In source-present mode, copy `supportedSurfaces`, `inputGates`, and `claimedCapabilities` from the same fresh schema-2 scanner report without reinterpretation. Canonical surfaces are only `_current`, `_blank`, `Page`, `Widget`, `Agent Worker`, and `App`; sort metadata ledgers by ASCII code-point order and never duplicate an entry. Every scanner input maps to one distinct `UX-INPUT` gate, and the `Inputs` gates equal all and only those rows. Use `Inputs: none` only when the fresh scanner emits `inputGates: []`; then use the fixed `no-input` UX gate and prove its N/A scope. `Claimed capabilities` equals the inventory scanner's output exactly and equals all and only distinct `{family=...} {gate=...}` pairs in the capability matrix.

Every source-present import root must contain `aiui-audit-claims.json`, even when it intentionally declares no product-only capability. Its exact closed schema is `{"schemaVersion":1,"scopeClosed":true,"claims":[{"family":"<family>","surface":"<surface>","description":"<description>"}]}`; use `claims: []` to close an empty universe. The scanner records its path, presence, `scopeClosed`, SHA-256, and claim count. Reject extra keys, duplicate keys, duplicate claims, empty strings, non-canonical surfaces, and any other shape. Do not append prose-only claims to metadata. A descriptive claim never borrows an arbitrary same-family/same-surface source item: the current schema cannot prove that unrelated code implements its prose. Each registered claim therefore remains a distinct `PROJECT-BINDING:UNRESOLVED` row with an ID ending `-PROVISIONAL` and result `BLOCKED`; an unknown family is quarantined as `project.unregistered`. Remove a claim only when product scope no longer includes it, not merely because similar code was found. Do not add an introduction or release judgment. Use ASCII version digits/punctuation; every capability row starts with the same canonical version and contains no different AIUI version.

The only exception is `Project revision: UNAVAILABLE`: there is no import root to scan. In that disclosed state, build the closed ledger only from capabilities explicitly scoped by the current request, keep every exact-family project binding provisional, and keep every generic source-policy family at its fixed provisional contract. The metadata ledger still equals the matrix exactly; the request cannot turn a binding or executed layer into `PASS`.

Resolve a 40-character revision in the audited repository and compare its Git tree to every current import-root path, mode, and byte. Do not trust the index, `.gitignore`, or `git diff`; ignored files still change Studio input. Reject symlinks, gitlinks, and non-regular entries. For uncommitted source, run `python3 <skill-root>/scripts/fingerprint_aiui_project.py <import-root>` and copy its exact `WORKTREE:` value. The fingerprint includes all regular source-root files except top-level `.git/` and `.aiui-evidence/`; never add another exclusion or accept an arbitrary identifier. If source cannot be inspected, use `UNAVAILABLE` for both revision and import root rather than borrowing an official documentation revision.

An exact project revision means either a verified 40-character commit/`WORKTREE:` fingerprint or the explicit `UNAVAILABLE` disclosure when the project was not supplied. `UNAVAILABLE` is not an omitted revision. In that state write exactly `Project revision: UNAVAILABLE` and `Import root: UNAVAILABLE`; request text may select a family, gate, or declared surface, but cannot establish a project binding or executed evidence. Do not invent a commit, route, handler, callback, permission, or runtime symbol.

`Supported surfaces` lists only the canonical surfaces emitted by inspected project source. A preview observation does not prove that the list is complete. If source is unavailable, write exactly `Supported surfaces: UNAVAILABLE` and keep `UX-TARGET` blocked. If source is present but the scanner emits an empty surface ledger, also write `Supported surfaces: UNAVAILABLE` and keep `UX-TARGET` blocked; include `page.target` only when the exact scanner/claims capability ledger contains it. Do not infer `_blank` from the word “Page.”

## Result contract

- `PASS` means every named evidence layer was executed and supports the criterion. Map every layer exactly once as `LAYER=kind:locator`, separated by ASCII semicolons. An exact family cannot pass while its API/event or declaration remains unknown; its code symbol and declaration must match the verified PASS-binding table below, not merely mention a related word. A `DEVICE` pass/fail also requires the exact physical Rokid device tuple in both audit metadata and the row.
- `FAIL` means every layer named in that row has executed evidence that contradicts the criterion. Use the same exact mapping. If one layer fails while another is unexecuted, create uniquely suffixed `-FAIL` and `-BLOCKED` rows; never put both outcomes in one row.
- `BLOCKED` means every layer named in that row is unproved. Map every layer exactly once as `LAYER=blocked:reason`. `Not tested`, `unverified`, and missing evidence are blocked reasons, never executed locators.
- `N/A` is available only to a conditionally applicable UX criterion excluded by both shipped source and product scope; an inventoried capability is already applicable and cannot be `N/A`. Applicability comes from a closed validator registry: `UX-TARGET` applies to a declared Page/Widget target surface and otherwise stays `BLOCKED` when target surfaces are unavailable; `UX-STATE`, `UX-TEXT`, `UX-VISUAL`, and `UX-ENVIRONMENT` apply to Page/Widget UI; `UX-FOCUS` applies when focus, action, or input families exist; each fresh scanner input gate makes its `UX-INPUT` row applicable; `UX-RECOVERY` applies when an inventoried network, camera, voice, world-awareness, gesture, worker, or unregistered capability can fail; `UX-LIFECYCLE` always applies; `UX-MOTION` remains scope-conditional. A worker-only project may therefore scope UI-only families to N/A, but cannot scope away lifecycle or an inventoried failure path. An exact empty scanner input ledger uses only the fixed `no-input` N/A gate. Use the exact shape `SCOPE: source=manifest:<path>@sha256=<manifest-hash>#<entry>; claim=manifest:<path>@sha256=<manifest-hash>#<entry>`. The two distinct manifest entries use `kind=scope`, `result=N/A`, bind the row and project revision, and identify `scopeAspect=source` or `scopeAspect=claim`. The source entry binds the current inventory path/hash, the validator's family-specific applicability query, and replayed `matches=[]`; the claim entry binds the import-root `aiui-audit-scope.json` path/hash with schema 1, `closed:true`, a closed `uxCriteria` universe, the same query, and replayed `matches=[]`. This scope file contains no revision field because it is itself included in the source fingerprint. Two self-written “absent” text files are not proof. Lack of time, credentials, source access, execution, or hardware is `BLOCKED`, not `N/A`.

For executed evidence, use only the layer-compatible kinds below. A single-source `SOURCE` cell may cite its one commit-pinned official URL directly. Every other locator is `manifest:<repository-relative-manifest.json>@sha256=<manifest-SHA-256>#<entry-id>`; verify the manifest hash before parsing it and reject duplicate JSON keys. Multi-source `SOURCE` evidence must use a manifest whose `inspectedSourceUrls` equals the row's complete URL set.

Use manifest schema 2. Its `subject` binds the exact project revision and import root. `sourceSnapshot` binds a freshly recomputed import-root fingerprint, the schema-2 inventory path/hash, and its capture time; `completionSnapshot` binds the same recomputed fingerprint after all captures. Every entry must start at or after the source snapshot and finish no later than the completion snapshot. A changed fingerprint makes every captured result stale. The manifest's tokenized `argv[]` is immutable provenance only: the validator checks its shape and bindings but never executes it. Evidence capture is a separate, pre-validation operation owned by the named authority.

Every entry binds a unique capture ID, collector name/version, matrix row ID, semantic gate, layer, kind, exact `PASS`/`FAIL` result, normalized criterion, non-placeholder observed outcome, project revision, start/capture times, artifact role, media type, byte length, repository-relative artifact path, and SHA-256. Executed STATIC/LOGIC command output and every `command` entry also bind `operation`, tokenized `argv[]`, `cwd` equal to the import root, `tool={"name":"...","version":"..."}`, integer `exitCode`, and exact `stdoutSha256`/`stderrSha256`; one output hash must equal the referenced artifact. A tiny text file saying “passed” is not command evidence. Capability entries additionally bind the exact normalized `target`, `apiBinding`, `declarationBinding`, and complete `sourceUrls`.

AIX command entries use `environment={"tool":"aix","toolVersion":"...","host":"..."}` and an `aix-preview`, `aix-pack`, `aix-list`, or `aix-validate` operation; a naked AIX log/artifact is invalid. Studio entries use `environment={"studioVersion":"...","hostRuntime":"..."}`. The Studio `hostRuntime` and device `runtimeVersion` must equal the audit's exact canonical `AIUI <version>`; a version-like substring in a generic host/build label is not a runtime binding. Device entries add `physicalDevice:true`, a non-reversible 64-hex `deviceIdHash`, capture tool and session ID to the matching model/host/runtime fields. These self-declared fields are not authenticity proof.

Pass one absolute `--trust-policy <outside-repository.json>` whose schema is `{"schemaVersion":1,"authorities":{"RUNNER":{"publicKeyPath":"<absolute external path>","publicKeySha256":"<64-hex>"},"STUDIO":{...},"DEVICE":{...},"SCOPE":{...}}}`. Include only roles used by the audit. Every key path and the policy itself must resolve outside the audited repository. `publicKeySha256` is the SHA-256 of the key's canonical SubjectPublicKeyInfo DER produced by `openssl pkey -pubin -outform DER`, not the PEM file bytes; every fingerprint must match and each role must resolve to a distinct canonical public key. `RUNNER` attests executed command/log/artifact collection and AIX capture; `STUDIO` and `DEVICE` attest their respective environments in addition to `RUNNER` where that entry kind requires it; `SCOPE` independently attests each N/A absence proof. A standalone `--trusted-device-public-key`, a repository-selected key, one public key reformatted under several roles, a reused all-roles key, or an unsigned self-report is rejected. Without the required authority, keep that layer `BLOCKED`. Reject simulator, emulator, browser, mock, test, TBD, and future-time device evidence.

The UX criterion is the `Test` cell. The capability criterion is exactly `Positive=<Positive path>; Negative=<Negative/fallback path>; Lifecycle=<Lifecycle/cleanup>`. Verify all paths stay inside the audit root, every path component is non-symlink, every artifact is non-empty and stable while read, every field/size/hash matches, and screenshot/recording bytes have the declared media signature. Across the whole audit, one artifact SHA-256 and one capture ID each belong to one evidence entry; copying, renaming, hard-linking, or re-encoding a capture does not create new proof. A request fact may establish a defect via `source:request://current#<verbatim request substring>` only on a `FAIL` row; it cannot establish `PASS`.

A natural-language request statement that validator, unit, AIX, Studio, or device checks passed is context, not an executed locator. Without an accepted schema-2 manifest and current-revision artifact, map each affected layer to `blocked:current-revision evidence not supplied`. Results captured before a source or interaction change cannot prove the changed project. `request://` remains limited to an explicit defect on a `FAIL` row and never upgrades a prior pass.

Reject absolute paths, traversal, backslashes, encoded traversal, stale revisions, wrong row/layer/binding metadata, descriptive placeholders such as `fake.log`, `not tested`, `未提供`, `未执行`, or a filename that does not exist. Production manifests and every evidence artifact stay below repository-root `.aiui-evidence/`; only the test harness has an explicit fixture-mode exception. The closed `aiui-audit-scope.json` product-scope universe stays inside the fingerprinted import root, not the evidence directory. A pre-change artifact cannot prove a post-change build. Content-addressing makes evidence tamper-evident, not independently authentic: use trusted CI/device attestation when authenticity is a release requirement.

| Layer | Allowed executed `kind` |
| --- | --- |
| SOURCE | `source` |
| STATIC | `source`, `command`, `log`, `artifact` |
| LOGIC | `command`, `log`, `artifact` |
| AIX | `command`, `screenshot`, `recording` |
| STUDIO | `log`, `screenshot`, `recording`, `artifact` |
| DEVICE | `log`, `screenshot`, `recording`, `artifact` |

For a release critical path, any applicable `FAIL` or `BLOCKED` means the work must not be described as complete or release-ready. A narrower statement such as “local deterministic checks pass; device UX is blocked” is valid.

## Evidence ladder

| Layer | Can establish | Cannot establish |
| --- | --- | --- |
| SOURCE | Target-version support from an exact official page and runnable sample | Project behavior or host availability |
| STATIC | Manifest, routes, declarations, bindings, source invariants, and import-root structure | Runtime semantics or usable UX |
| LOGIC | Deterministic state, boundaries, failures, fallback, and cleanup in executed code | Host event delivery, permissions, or optics |
| AIX | Advertised pack/list behavior and basic browser Ink rendering/events | Studio compatibility or physical hardware behavior |
| STUDIO | Authenticated import and host-like Web simulation on the selected runtime | Physical optics, sensors, keys, thermals, or endurance |
| DEVICE | Behavior on the named glasses/runtime in real visual and input conditions | Platform review approval or future compatibility |

An AIX/browser preview must not be used as proof of physical focus, keys, voice, gesture, permission, optics, or performance. Likewise, source or static evidence cannot replace execution.

## Project UX evidence matrix

Put the completed table under the exact H2 heading `## Project UX evidence matrix`. Copy these rows into the project audit and preserve every column exactly as written. Do not rename, merge, or omit `Risk`, `Evidence layer`, `Result`, `Evidence`, or any other required column. Split a row when surfaces, states, inputs, or evidence layers have different results; never hide a blocked required layer inside a combined `PASS`. Fill every cell and do not collapse applicable rows into prose.

Start every UX `ID` cell with `[UX-...] {gate=<semantic-instance>}`. The gate names one independently releasable surface, state group, input path, or other criterion. Each gate—not merely the family-wide union—must cover every required family layer exactly once. All split rows for one gate keep byte-for-byte-equivalent `Surface/state`, `Risk`, and `Test` contracts; split IDs expose their result with `-PASS`, `-FAIL`, or `-BLOCKED`. If the contract changes, create another gate.

Expand `UX-INPUT` into unique gates for every applicable scanner path. When they are in scope, tap, Enter, Back, directional/root scroll, component scroll, voice, and gesture are separate rows; a combined “tap/key” row is invalid. Each path must cover `LOGIC, STUDIO, DEVICE` and cannot be N/A. If and only if the scanner emits no input gates, write `Inputs: none`, use `[UX-INPUT] {gate=no-input}`, retain the same canonical cells/layers, and supply the two SCOPE-signed N/A entries. Apply the same split rule to known failures: for example, `[UX-VISUAL-STATUS-FAIL] {gate=status-meaning}` can hold an executed `STATIC` failure while `[UX-VISUAL-STATUS-BLOCKED] {gate=status-meaning}` holds unexecuted AIX/device layers.

## Per-capability matrix

Put the completed table under the exact H2 heading `## Per-capability matrix`. First run `python3 <skill-root>/scripts/inventory_aiui_capabilities.py <import-root> --target-version <version>`. Reconcile its content-bound `claimedCapabilities`, every `unmatchedSymbols` hit, `versionViolations`, and explicit product claims against the source. The scanner fingerprints before and after its scan, rejects duplicate manifest keys, records exact API/declaration bindings and source positions, and quarantines unregistered platform-looking symbols instead of guessing support. Comments or generated files may still create conservative candidates; never silently discard one. Inventory every distinct component type, runtime/API symbol, template-bound event, exported App/Page host or lifecycle callback, manifest declaration or permission, route/target behavior, and promised hardware capability. “Used” includes direct calls, imported code, template bindings, configuration, fallbacks, and claimed behavior. Every inventory item maps to at least one row; zero unaccounted items are allowed. Every unmatched scanner item maps one-to-one to a `project.unregistered` quarantine row; it blocks release but is not omitted.

Start every `Capability` cell with a unique stable identifier, family, and semantic gate, such as `[CAP-NETWORK] {family=network.unknown} {gate=network-transport} Network transport unresolved`, followed by a human-readable label. Each of the three behavior cells starts with the family's exact `{contract=cap-<dotted-family-as-hyphens>-v1}` and its exact `{path=positive|negative-fallback|lifecycle-cleanup}` token, followed by the registered canonical description. Every gate covers its family's fixed layer union exactly once; one button, input, or surface cannot lend evidence layers to another. Split rows retain the same family/gate and exactly the same version/surface, normalized API, declaration, source set, positive path, negative path, and lifecycle contract; their IDs expose the result. Changing `fetch(...)` to `wx.request(...)`, changing surface, or changing any contract cell requires a new gate. Do not combine distinct symbols or events in one row.

Host focus, element focus/binding, each input mode and non-sensor fallback, a hardware permission/declaration, and the runtime API that consumes it are separate inventory items. Keep an umbrella inventory or source-completeness ledger in `Claimed capabilities`, not as a capability row. Repeated instances may share a row only when their exact version, mechanism, declaration, source set, contracts, required evidence layers, result, and evidence are identical. Unknown families cannot pass until a family policy is registered.

Every `Version/device/surface` cell starts with exactly one canonical `AIUI 0.17.0` or `AIUI 0.18.0` token; never abbreviate it to `0.17`, say “same as above”, or list multiple versions. Then name the device/host and surface, using `UNAVAILABLE` for missing values. An executed DEVICE row repeats the exact audit tuple.

If source is unavailable or the exact symbol is unresolved, create one named provisional `BLOCKED` row for each disclosed capability family and state what must be inspected; uncertainty is never a reason to omit or combine rows. For a disclosed Page, inventory target/routing, host focus, each actionable element's focus/binding, every named input, fallback, hardware permission, hardware runtime call, and retained lifecycle work separately. Preserve every column exactly as written. This includes routing, network/streams, storage, timers, camera/media/recording, speech, sensors/Bluetooth, Canvas, Page world awareness, and targeted Widgets or Agent Workers. Remove a row only after both shipped code and product claims remove the item, and record that scope decision.

### Project-binding provisional protocol

Platform-policy registration and project-binding inspection are independent states. For a registered family whose project binding was not inspected, keep its canonical ID base, `{family=...}`, exact registered source set, and complete layer union. Append `-PROVISIONAL` to the bracketed ID and write exactly `PROJECT-BINDING:UNRESOLVED` in both binding cells. The result is `BLOCKED` and every layer uses `blocked:reason`. The two binding cells contain only that sentinel. Other cells may name observable behavior such as camera denial or voice no-match, but never candidate machine symbols, callbacks, handlers, routes, declarations, or permission identifiers. Request prose may select a family, but cannot replace project-source inspection. Do not swap the registered source policy for `SEARCH-SCOPE`. Once inspected, remove `-PROVISIONAL`, write both normalized bindings, and retain `BLOCKED` only for genuinely unexecuted layers.

For a scanner item with no registered family policy, use its quarantine gate `unregistered-<key>` and emit `[CAP-UNREGISTERED-<KEY>] {family=project.unregistered} {gate=unregistered-<key>} Unregistered project capability`; `<KEY>` is the scanner's 12-hex key uppercased. Copy the scanner's `PROJECT-SYMBOL:...` `apiBinding` exactly into `API/component/event`, or use `PROJECT-BINDING:UNRESOLVED` for a claim-only item, and write exactly `UNKNOWN — source policy not registered` in `Declaration/permission`. Use exactly SEARCH-SCOPE=[AIUI documentation index](https://github.com/yodaos-project/AIUI/tree/88e70bb0382525c1a93ef077c2401dcc31a273ce/documentation); SEARCH-SCOPE=[AIUI samples index](https://github.com/yodaos-project/AIUI/tree/88e70bb0382525c1a93ef077c2401dcc31a273ce/samples), all six evidence layers, and `BLOCKED`. Its behavior cells are exactly `{contract=cap-project-unregistered-v1} {path=positive} The declared capability performs its claimed outcome once`; `{contract=cap-project-unregistered-v1} {path=negative-fallback} Unavailable, rejected, or ignored delivery preserves an explicit fallback`; `{contract=cap-project-unregistered-v1} {path=lifecycle-cleanup} Hide/show and unload do not retain stale capability work`. This quarantine is not a support policy and can never pass. Remove it only when a new current-revision inventory no longer reports the token and explicit product claims no longer contain it; record removal in audit history, not as capability `N/A`.

## Required final decision

The complete audit contains only the seven metadata lines, the two required H2 matrix sections/tables, and this final H2 section. Do not put prose between those structures or after the final section.

```text
## Final release decision

Final status: PASS | FAIL | BLOCKED
Release-ready: YES | NO
Reason: FAIL=[comma-separated exact row IDs or none]; BLOCKED=[comma-separated exact row IDs or none]
Required gates: none, or comma-separated exact ID@LAYER pairs
```

Each field appears exactly once. The two `Reason` ledgers equal all and only matrix rows with those results. When a blocker exists, `Required gates` equals every evidence layer of every `FAIL` or `BLOCKED` row, one `ID@LAYER` pair each, with no omissions, duplicates, or extras. If either matrix contains an applicable `FAIL` or `BLOCKED`, `Final status` cannot be `PASS` and `Release-ready` must be `NO`. This structured section is the sole release decision; do not contradict it elsewhere.

Decision severity is deterministic, with precedence `FAIL` then `BLOCKED` then `PASS`: any `FAIL` row makes the final status `FAIL`; otherwise any `BLOCKED` row makes it `BLOCKED`; only an audit with neither is `PASS`. A ledger ID is the bracketed token only, without brackets, backticks, `{family}`, `{gate}`, or label—for example `CAP-CAMERA-RUNTIME-FAIL`. A gate is `<ledger-ID>@<LAYER>`, for example `CAP-CAMERA-RUNTIME-FAIL@STATIC`. Sort every non-`none` ledger by ASCII code-point order and write lowercase `none` exactly.

The four field labels may not appear elsewhere in the audit. When gates remain, `Required gates` must name a blocking matrix ID or evidence layer; `none`, `no remaining gates`, and equivalent wording are valid only when every applicable row passes. Avoid any release approval or completion statement outside this section, even as a quoted instruction.
