# Independent AIUI 0.19 forward evaluation

The response below was produced by a fresh agent using only the packaged Skill, relevant references, and the fixed official source snapshot. It addresses a hypothetical product request; it does not claim that this repository implemented that product. The original temporary audit was copied here for repeatable validation.

---

可以按 AIUI 0.19.0 做 Page 打开城市 Widget、短期 Worker 和实时音频，但原需求中的 `background`、`wx.showToast`、WebRTC 视频和权限判断需要先修正。以下依据本地可读的官方固定快照 `7d62c2d9ac1cdc1389ba06ed0651b395903accff`；该快照的 changelog 明确标为 v0.19.0。这里给出实现前方案与验收设计，没有实现产品，也没有运行产品测试。

已使用仓库的 `rokid-aiui-agent` 技能及其 0.19、版本来源、运行能力、验收和 AIX 参考。固定快照是 API 合约来源，不是待建产品的版本或测试证据。

| 需求 | 0.19.0 边界与修正 |
| --- | --- |
| Page 打开 Widget，传 `city` | 支持。Widget 在 `app.json.widgets` 声明 `placement: "overlay"`，用 `window.open('widgets/weather/index?city=hangzhou', '_widget')`；路径不带 `.ink`。`onCreate(options)` 收到字符串参数，无 query 时为 `{}`。`window.open()` 返回 `undefined`，不返回实例或打开结果，不能据此宣布打开成功。见[路由](https://github.com/yodaos-project/AIUI/blob/7d62c2d9ac1cdc1389ba06ed0651b395903accff/documentation/3-api/route.en-US.md)、[Widget API](https://github.com/yodaos-project/AIUI/blob/7d62c2d9ac1cdc1389ba06ed0651b395903accff/documentation/3-api/framework/widget.en-US.md)。 |
| `background` Worker | 不支持该 lifetime；值被保留，当前会使配置验证失败。使用 `agentWorkers`，一次短任务选 `instant`，有 Page 或 Widget 打开期间保留任务选 `foreground`；当前只支持一个 `open` trigger。Worker 没有 `window`、`document`、`fetch`、UI、路由、媒体采集或 WebRTC。`onOpen()` 中必须在同步返回前调用 `event.waitUntil(promise)`，仅将函数声明为 `async` 无法延长寿命。见[Agent Worker](https://github.com/yodaos-project/AIUI/blob/7d62c2d9ac1cdc1389ba06ed0651b395903accff/documentation/1-framework/open-agent-format/agent-worker.en-US.md)。 |
| `wx.showToast` 提示结果 | 固定版本的[兼容 API 清单](https://github.com/yodaos-project/AIUI/blob/7d62c2d9ac1cdc1389ba06ed0651b395903accff/documentation/3-api/weixin-compatible-apis.en-US.md)没有列出 `wx.showToast`，不能从微信小程序经验推断支持。默认改成 Page/Widget 自己渲染的状态提示组件：操作中、成功、失败、重试；成功文案必须等待实际业务结果。 |
| WebRTC 音频和视频 | 0.19 新增 `RTCPeerConnection`、`RTCDataChannel`，支持音频、文本和二进制数据，明确不支持视频传输；可用于 Page/Widget Window 环境，不用于 Worker。视频采集/录像支持不等于 WebRTC 视频支持。见[WebRTC](https://github.com/yodaos-project/AIUI/blob/7d62c2d9ac1cdc1389ba06ed0651b395903accff/documentation/3-api/media/webrtc.en-US.md)。 |
| `wx.canIUse() === true` 当作授权 | 不成立。它只匹配环境初始化时注册的兼容函数路径，传入不带 `wx.` 的准确函数名；namespace、未知路径、参数选项路径和应用新增函数不能算支持。`true` 不证明硬件、权限、设备就绪或操作成功。WebRTC 全局类也不能用猜测的 `wx` 路径检测。见[兼容 API](https://github.com/yodaos-project/AIUI/blob/7d62c2d9ac1cdc1389ba06ed0651b395903accff/documentation/3-api/weixin-compatible-apis.en-US.md)。 |

Widget 和 Agent Worker 本身在 0.18 已引入；0.19 新增的是 Widget query 传递、WebRTC 音频/数据等，不应把这些都当作 0.19 首次出现。版本决策以本次固定快照为准，不把 `latest` 当作永久等于 0.19。见[版本更新记录](https://github.com/yodaos-project/AIUI/blob/7d62c2d9ac1cdc1389ba06ed0651b395903accff/documentation/8-changelog/latest.en-US.md)。

建议采用以下可实现结构：

1. 一个明确以 `_blank` 运行的 Page 负责城市选择、打开 Widget、音频授权/采集、信令和 WebRTC 会话。若还支持 `_current`，它只保留可用的城市摘要及引导；每个目标单独验收。媒体采集文档要求进入 `_blank`，且 `app.config.lifetime === 'cut'` 时不可用，所以暂不承诺 overlay Widget 能直接采集麦克风。Widget 有 WebRTC Window API 不会消除这项采集限制。见[媒体采集限制](https://github.com/yodaos-project/AIUI/blob/7d62c2d9ac1cdc1389ba06ed0651b395903accff/documentation/3-api/media/media-capture.en-US.md)。
2. 城市 Widget 选 `1x2` overlay，在 `.ink` 的 `<script def>` 中保持同样的 family，并使用 `<widget>` 根；按宿主实际尺寸布局。Page 对 city 做编码，Widget 对 `options.city` 做类型、空值、长度和业务允许值检查，缺失时使用明确默认城市。初始化放 `onCreate`，可见工作放 `onAttach`，隐藏时暂停，销毁时取消。重复开关可能生成新实例，不能依赖旧实例保留。见[Widget 开发](https://github.com/yodaos-project/AIUI/blob/7d62c2d9ac1cdc1389ba06ed0651b395903accff/documentation/1-framework/open-agent-format/widget.en-US.md)。
3. Worker 采用 `foreground`，只承担其支持范围内的临时任务状态/去重初始化；每次 Page 或 Widget 打开都可能触发 `onOpen`，用在途 Promise 防止重复初始化。UI、网络请求和 RTC 留在 Window；不假设文档未给出的 Page↔Worker 消息桥。若业务要求所有 Page/Widget 关闭后还持续通话，当前 Worker 合约无法满足，需另选已验证宿主方案。
4. 实时方案先定为音频加数据。应用另备真实信令服务交换 SDP/ICE，并配置真实 STUN/TURN 和凭据；蓝牙链路上的 HTTPS 成功不能证明眼镜可连通 WebRTC。远端 description 设置完成前排队 ICE；通道仅在 open 时发送，单条数据不超过 256 KiB 及更小的协商限制，并用 bufferedAmount 做有界背压。音频接收要接入 Web Audio 输出；浏览器预览还可能需要 HTTPS/localhost、浏览器授权和用户交互后 resume。连接成功以双方接收结果和连接统计确认。
5. 发送音频时仅声明所需的 `RECORD_AUDIO`，再处理系统授权及 `getUserMedia({audio:true})` 的真实结果；接收音频本身不需要麦克风权限。city 参数不需要定位权限。不能因 `canIUse` 或 manifest 声明就显示“已授权”；拒绝、撤销和无硬件都要保留退出/重试或文字数据路径。0.19 已移除单独的 `SPEECH_RECOGNITION` 权限。见[manifest 权限](https://github.com/yodaos-project/AIUI/blob/7d62c2d9ac1cdc1389ba06ed0651b395903accff/documentation/1-framework/open-agent-format/app-json.en-US.md)、[WebRTC](https://github.com/yodaos-project/AIUI/blob/7d62c2d9ac1cdc1389ba06ed0651b395903accff/documentation/3-api/media/webrtc.en-US.md)。
6. 视频保留为明确的产品决策门：若实时视频不可删减，0.19 方案当前不能满足；需要单独验证其他宿主/版本。若可接受非实时视频，可另行评估 Page 采集、MediaRecorder 录制后通过 HTTPS 上传完整视频的方案，额外声明 `CAMERA`，用静态 `MediaRecorder.isTypeSupported()` 选择格式。这是录制上传的降级，不作为实时视频验收，也不把数据通道传二进制描述成已支持的视频通话。见[视频录制](https://github.com/yodaos-project/AIUI/blob/7d62c2d9ac1cdc1389ba06ed0651b395903accff/documentation/3-api/media/media-capture.en-US.md)。

若随后开始实现，先检查项目连续性文件，再增量修改独立 Agent 项目内的 `AGENTS.md`、`app.json`、应用入口、Page、Widget、Worker、状态提示组件、必要资源和测试，以及 `aiui-audit-claims.json`。最终交付完整 Studio 可导入源码目录；支持且实际成功执行 pack/list 时再附加源码目录外的 `.aix`。本次仅做前置分析，没有创建这些产品文件。

功能与 UX 验收按下表设计；下列全部是计划，当前结果均为 `BLOCKED`：

| 范围 | 正向验收 | 负向/恢复与生命周期验收 |
| --- | --- | --- |
| Page→城市 Widget | 打开已声明 overlay，`city=hangzhou` 确认显示杭州；合法 Unicode 城市正确传递；Widget 真正呈现后才认为可用。 | 无 query 收到 `{}`；空值、长中文/英文、混合 Unicode、未知 city、非法值有明确默认/纠正路径；缺少路径/family 不一致不伪报成功。反复 attach/detach/关闭重开不重复计时、请求或监听。 |
| Worker | 一个 open 启动一个受控操作；重叠 open 复用在途初始化；异步任务被 waitUntil 完整跟踪。 | 配置 background、无效 script、第二个 open worker、异步返回后才 waitUntil 均受控拒绝；拒绝/超时可观察；instant 结算后停止，foreground 最后 UI 关闭后不承诺继续，重启状态不当作永久存储。 |
| 提示和状态 | loading→ready/active→success/error 的文案反映真实业务结果；短提示之外仍有可恢复状态。 | 不支持 API、打开未完成、失败、重复操作不显示虚假成功；错误有重试/退出；城市、连接状态、授权状态分开表示。 |
| 授权和采集 | 在目标 `_blank` 请求麦克风，实际获得 audio track 后显示采集中；只接收时不请求麦克风。 | 首次拒绝、后续撤销、无设备、不可满足约束、cut lifetime、非允许 surface 均不崩溃、不绕过；canIUse 为 true 但授权拒绝时仍显示拒绝，false/未知路径有降级。 |
| RTC 音频与数据 | 两端完成实际 SDP/ICE 交换，互收准确文本/二进制，音频可听且统计显示媒体传输；测试真实 TURN relay。 | 信令成功但 ICE 失败、TURN 过期/缺失、离线/超时、断连重连、ICE 先到、协商冲突、通道未开时发送、超大消息及慢接收均有有界队列和可用重试/退出；真实网络错误不被 online 标志遮蔽。 |
| 清理 | Page unload 或 Widget destroy 后关闭 channel、peer、音频上下文，停止每条本地 track，取消网络与监听。 | pc.close 本身不当作本地 track 已停止。hide/show 明确暂停或恢复；连续开关不出现后台收音、残留声音、重复回调、晚到响应覆盖新 city。 |
| 输入、焦点与可读性 | 实现时选定每个具体输入路径，并逐个验收单次激活、宿主/元素焦点、返回和固定操作可达；Widget 遵守 interactive 状态。 | 未拥有输入保持宿主默认，不滥用 preventDefault；重复/忽略事件不重复操作；无传感器的操作路径可用。长文案不遮住退出/重试；亮、暗、杂乱真实背景上状态/焦点均清楚，不只靠颜色或短暂提示。 |
| 性能与长期使用 | 记录冷启动到首个可见/可用状态、请求/重连延迟、重复导航和连续使用的内存趋势。 | 动画、网络和音频叠加下检查卡顿/热量/稳定性；先订项目基线和预算，不编造官方毫秒阈值。 |
